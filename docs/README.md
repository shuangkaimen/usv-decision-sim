# 项目文档导航

本目录采用“核心技术文档 + 开发实践指南”的结构。核心文档描述当前项目长期有效的接口、边界和建模约定；指南文档记录具体开发活动中的工具使用和验证方法。

## 推荐阅读顺序

1. [系统架构](architecture.md)：了解模块职责、依赖边界和数据流。
2. [API 与接口契约](api.md)：了解当前 `UsvAgent` 的公共接口和状态不变量。
3. [仿真与运动学](simulation.md)：了解坐标系、单位、离散运动学和更新顺序。
4. [算法与决策边界](algorithm.md)：了解 State、Observation、Action 以及算法层职责。
5. [测试与验收](testing.md)：了解测试入口、验收矩阵和扩展测试边界。
6. [项目知识与建模约定](knowledge.md)：核对已经冻结的跨模块事实和变更规则。

## 核心技术文档

| 文档 | 主要回答的问题 |
| --- | --- |
| `architecture.md` | 模块如何划分，谁可以依赖谁？ |
| `api.md` | 当前公共接口是什么，输入输出和错误边界是什么？ |
| `simulation.md` | 状态如何推进，单位、坐标和更新顺序是什么？ |
| `algorithm.md` | 策略、规划器、Environment 和 Agent 如何协作？ |

| `knowledge.md` | 哪些建模语义已经冻结，修改时需要遵守什么规则？ |

## 开发实践指南

- [日志与调试](guides/logging_and_debugging.md)：日志工具约定、调试测试矩阵和验证命令。

开发实践指南可以随着项目演进增加，但不应替代核心技术文档中的接口和架构契约。实验配置与实验结果优先放在 `experiments/`，不在本目录堆积运行产物。

## 当前阶段

当前项目处于单 USV 二维平面运动学实体阶段。已实现的核心能力是 `UsvAgent` 的状态管理、动作限幅、离散运动学更新和输入校验；Day9 新增 `UsvControlMlp` 教学原型与最小训练脚本，用于验证训练链路。完整 Environment、奖励、碰撞检测、PPO 和多智能体模块仍属于后续阶段。
